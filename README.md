# Claude Agent Hub

tmux 上で複数の Claude Code セッションを起動し、ブラウザから状態の確認・切り替え・対話を行うローカルハブです。
状態の判定は画面のスクレイピングではなく、Claude Code の **hooks** から届くイベントを基にしています。

## 必要なもの

- Node.js 20 以上（外部パッケージは不要）
- tmux 3.0 以上
- Claude Code（`claude` コマンド）

## 起動

```bash
npm start
# → http://localhost:4317
```

エージェントは tmux セッション `agent-hub` の各ウィンドウで動きます。端末から直接操作する場合は `tmux attach -t agent-hub` を実行してください。

## 仕組み

```
claude (tmux pane) ──hook──▶ hooks/hub-hook.cjs ──append──▶ ~/.agent-hub/events/<agentId>.jsonl
                                                                   │ fs.watch
                                                                   ▼
                     ブラウザ ◀──SSE── server.js（状態機械） ──▶ tmux @hub_state（ステータス行の色分け）
                        │                    │
                        └─send/keys─▶ tmux paste-buffer / send-keys
                                             └─▶ transcript JSONL を読み取って会話表示
```

- hook 設定は `~/.agent-hub/hooks.json` に生成し、`claude --settings` で渡します。グローバル設定（`~/.claude/settings.json`）は変更しません。
- hook は環境変数 `AGENT_HUB_AGENT` が設定されたセッションでのみ動作し、常に終了コード 0 で終了します。
- 状態の解釈はサーバ側（`lib/store.js` の `applyEvent`）で行います。

| hook イベント | 状態 |
|---|---|
| SessionStart | 待機中 |
| UserPromptSubmit / PreToolUse / PostToolUse | 実行中 |
| PermissionRequest / Elicitation / Notification(permission_prompt) | 要対応 |
| Stop / StopFailure / Notification(idle_prompt) | 応答完了 |
| PreCompact | 圧縮中 |
| SessionEnd / ペインのプロセス終了 | 終了 |

## ブラウザからの回答

Claude Code の対話ダイアログは、ブラウザの「回答待ちパネル」からも回答できます。

| 種類 | 元のツール / イベント | ブラウザでできること |
|---|---|---|
| 質問 | AskUserQuestion | 単一選択・複数選択・その他（自由記述）・選択肢の説明とプレビュー図の表示・メモの添付・選択せずに返信・回答しない |
| 計画の承認 | ExitPlanMode | Markdown（表・mermaid 図を含む）で計画を表示、承認時のモード選択（auto / 編集を自動承認 / 都度確認）、修正依頼 |
| 権限の確認 | 通常のツール | コマンド・差分・書き込み内容の表示、許可、許可して記憶（提案ルールの選択）、理由付きの拒否、作業の中断 |
| 入力要求 | MCP Elicitation | スキーマからフォームを生成（文字列・数値・真偽値・選択肢・複数選択）、送信・辞退・キャンセル、URL モード |

仕組み:

- `PermissionRequest` hook は TUI のダイアログと**並行して**動作します。ブラウザとターミナルのどちらで回答しても、先に回答した方が採用されます。
- ターミナル側で先に回答された場合、後続のイベント（PostToolUse など）から解決済みと判断し、待機中の hook を終了させます。
- `Elicitation` hook は TUI のダイアログより前に実行されるため、hook の待機中はターミナル側にダイアログが表示されません。ターミナルで回答する場合は、ブラウザで「ターミナルで回答」を押してください。
- 要求の内容は `~/.agent-hub/requests/`、回答は `~/.agent-hub/responses/` を介して受け渡します。
- ハブのサーバが停止している場合、hook は待機せず、すぐに TUI に処理を任せます。サーバは 5 秒ごとに `~/.agent-hub/server.json` を更新して、稼働中であることを知らせます。

会話タブでは、回答済みの質問・計画・TODO もカード形式で表示します。アシスタントの回答は見出し・リスト・表・引用・コードブロックを含む Markdown として表示し、```` ```mermaid ```` のブロックは図として描画します（mermaid は CDN から遅延読み込みし、オフライン時はコードのまま表示します）。

## タスクキューと送信

入力欄には 2 つの送り方があります。

| 操作 | 動作 |
|---|---|
| 送信（Enter） | 今すぐ送信します。作業中に送った場合は、作業の切れ目で取り込まれます（軌道修正や補足に使います） |
| キューへ（Ctrl+Enter） | キューの末尾に追加し、現在の作業が終わってから送信します（次の独立したタスクに使います） |

- キューは、エージェントが「応答完了」または「待機中」で、回答待ちのダイアログがないときに、先頭から 1 件ずつ自動で送信されます。
- 項目ごとに「/clear」を有効にすると、送信前に `/clear` で会話をリセットします。
- キューのパネルでは、ドラッグ＆ドロップまたは ↑↓ ボタンでの並べ替え、ダブルクリックでの編集、削除、一時停止・再開、先頭の即時送信ができます。
- 次の場合はキューを自動で一時停止します: エラーで停止した（StopFailure）、ハブから Esc / Ctrl+C で中断した、最後の応答に判断待ちの提案がある。
- **送信ガード**: 回答待ちのダイアログがある間や起動中は、tmux への送信を拒否します（ダイアログへの誤入力を防ぐため）。その場合はダイアログに回答するか、キューに追加してください。

## 提案の仕分け

ハブから起動したエージェントには、追加のシステムプロンプトで「個別に判断してほしい提案は ```` ```proposals ```` ブロック（JSON）で示す」よう指示しています。

- 最後の応答に未回答の提案ブロックがあると、仕分けボードが自動で開きます。
- 各提案カードを「採用 / 却下 / 修正して実施 / 未判断」の列へドラッグ＆ドロップするか、カードのボタンやキー（A 採用 / X 却下 / E 修正 / U 戻す）で仕分けます。「修正して実施」では修正内容を入力します。
- 「判断を送信」で、仕分け結果を整形した文章として Claude に送ります（「キューに追加」も可能）。
- 提案ブロックがない応答でも、箇条書きが 2 項目以上あれば、メッセージ右下の「仕分ける」から同じボードを開けます。
- 仕分けの途中経過はブラウザに保存されるため、画面を閉じても続きから再開できます。

※ 追加のシステムプロンプトは新規作成時と再起動時（新しいセッション）に適用されます。既存のセッションを `--resume` した場合は、最初の起動時の内容が引き継がれます。

## 猫のステータス表示

各エージェントの状態を、ドット絵の猫のアニメーションで表示します（サイドバーのカードと、ステータス行の帯）。

| 状態 | 猫の様子 |
|---|---|
| 実行中（ツール使用中） | 歩く（ステータス行の帯では左右に往復） |
| 実行中（思考中） | お座りして「…」 |
| 要対応 | 前足を振って「！」 |
| 応答完了（1 分以内） | 目を細めてしっぽを振り「♪」 |
| 待機中・応答完了 | お座り（ときどきまばたき） |
| 待機中・応答完了が 5 分以上続く | 丸まって昼寝（Zzz） |
| 起動中 | あくび |
| 圧縮中 | 毛づくろい |
| 終了 | 灰色で眠る |

- 毛色は作成時に選択できます（茶トラ / サバトラ / クリーム / シャム / 黒猫 / 三毛）。「おまかせ」の場合はエージェント ID から決まります。
- スプライトは `public/cats.js` に文字列で定義しています。OS の「視差効果を減らす」設定が有効な場合はアニメーションを停止します。

## 画面操作

- 左の一覧でエージェントを選択します。許可待ちのエージェントは点滅表示されます。
- 「会話」タブは transcript から整形した会話を、「ターミナル」タブは tmux 画面のスナップショットを表示します。
- 入力欄は Enter で送信、Shift+Enter で改行します。
- キー送信ボタン（Enter / Esc / 1〜3 / ↑↓ / Shift+Tab / Ctrl+C）で、許可ダイアログや信頼確認に応答できます。
- ショートカット: `Alt+↑↓` 切替、`Alt+1〜9` 選択、`Alt+W` 次の要対応エージェントへ移動。
- デスクトップ通知を有効にすると、非選択中のエージェントが許可待ち・完了になったときに通知します。

## 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `HUB_PORT` | `4317` | 待ち受けポート（127.0.0.1 のみ） |
| `HUB_TMUX_SESSION` | `agent-hub` | 使用する tmux セッション名 |
| `HUB_DEFAULT_MODEL` | `haiku` | 既定のモデル |
| `HUB_WORKSPACES` | `./workspaces` | 作業ディレクトリ未指定時の作成先 |
| `AGENT_HUB_HOME` | `~/.agent-hub` | 状態・イベント・hook 設定の保存先 |
| `HUB_CLAUDE_BIN` | `claude` | Claude Code の実行ファイル |

## 既知の制約

- Esc / Ctrl+C による中断では Stop hook が発火しないため、ハブ経由でキーを送った場合のみ「待機中」に戻します。tmux 側で直接中断した場合は状態が「実行中」のまま残ることがあります。
- 信頼確認ダイアログはセッション開始前に表示されるため、hook では検知できません（状態は「起動中」のままになります）。
- AskUserQuestion の「選択せずに返信」は、拒否メッセージとして Claude に返信内容を伝える方式です。
- ターミナルタブは色なしのスナップショット表示です。
