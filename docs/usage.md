## エージェントの作成と管理

左上の「＋ 新規」から、次の項目を指定してエージェント（Claude Code のセッション）を起動します。

| 項目 | 説明 |
|---|---|
| 名前 | 一覧と tmux のウィンドウに表示する名前（40 文字まで）。空欄の場合は `agent-<番号>` になります |
| モデル | haiku / sonnet / opus / fable から選びます（既定は haiku） |
| エフォート | 「ユーザー設定に従う」（`--effort` を渡さない）、low、medium、high、xhigh、max から選びます。指定した値は詳細画面の右上の「エフォート」に表示され、再起動しても引き継がれます。作成後も変更できます（[エフォートの変更](#エフォートの変更)） |
| 権限モード | 「ユーザー設定に従う」（`--permission-mode` を渡さない）、manual、acceptEdits、auto、plan から選びます |
| 猫の毛色 | [猫のステータス表示](#猫のステータス表示)の毛色です |
| 作業ディレクトリ | 既存のディレクトリを指定します（`~` も使えます）。空欄の場合は、名前の英数字・`_`・`-` 以外を `-` に置き換えた名前（使える文字がなければエージェント ID）のディレクトリを `workspaces/` の下に作ります（[設定](configuration.md)の `HUB_WORKSPACES`）。同じ名前のエージェントは同じディレクトリを使います |
| 最初の指示 | 入力すると、起動と同時に Claude に送ります |

- 作成直後は、信頼確認などのダイアログを確かめられるよう「ターミナル」タブが開きます。初めて使うディレクトリでは信頼確認ダイアログが表示されるので、キー送信ボタンで応答してください。
- 詳細画面の右上の「再起動」ボタンは、プロセスが動いている間は「終了」に切り替わります。
  - 「終了」は、確認の後でエージェントのプロンプトに `/exit` を送って Claude Code を終了させます。tmux のペインは残り、プロセスが終わると状態が「終了」になって、ボタンが「再起動」に戻ります。
  - 終了を送れるのは、状態が「応答完了」か「待機中」で、回答待ちのダイアログがなく、「引き継いでリセット」・キューの送信・起動し直しの最中でないときだけです。それ以外のときはボタンが無効になり、理由をボタンの説明に表示します。作業中のエージェントは、先に中断（Esc）してから終了してください。
  - 終了を送ってからプロセスが終わるまでは、キューの自動送信と入力欄からの送信を止めます。15 秒待っても終わらない場合は、終了の確認などのダイアログが開いているおそれがあるため、キューを一時停止して止めるのをやめます。ターミナルを確かめてから再開してください。
  - 「再起動」は、プロセスが終了したエージェントで押せます。会話の記録（transcript）があれば `--resume` で続きから、まだ会話がなければ新しいセッションで起動します。
- 「削除」は、作業中でも tmux のウィンドウを閉じてセッションを終了し、一覧とハブのイベント記録から取り除きます。作業ディレクトリと Claude Code の会話記録は残ります。覚えているウィンドウが別のエージェント（またはハブのものではないウィンドウ）に使われていた場合は、ウィンドウを閉じずに一覧と記録からだけ取り除き、そのことを表示します（[状態の判定](architecture.md#状態の判定)）。
- 「tmux で表示」は、tmux 側でそのエージェントのウィンドウを選択します（アタッチ中の端末があれば切り替わります）。

### エフォートの変更

詳細画面の右上の「エフォート」で、作成済みのエージェントのエフォートを変更できます。選択肢は作成時と同じです。

- 動いているエージェントは、保存値を更新してから、`--resume` で会話を引き継いだまま起動し直し、新しい `--effort` を付けます（「ユーザー設定に従う」は付けません）。会話の記録がまだなければ新しいセッションで起動します。起動し直すのに数秒かかります。
- ハブからは `/effort` を送りません。Claude Code の `/effort <レベル>` は、セッションだけでなく利用者の設定（`~/.claude/settings.json` のモデルごとの既定）にも保存し（`max` を除く）、`/effort auto` はその保存値を消すため、ほかのエージェントや新しいセッションの既定まで変わってしまうからです。
- 変更できるのは、状態が「応答完了」か「待機中」で、回答待ちの要求がなく、サブエージェント（実行中・要対応）や「引き継いでリセット」が動いていないときだけです。それ以外のときは選択欄が無効になり、API を直接呼んでも拒否します。
- 起動し直すと、次のものは元に戻ったり止まったりします。
  - バックグラウンドで動いている Bash などの処理は止まります。ハブはこれらを検出できないため、変更する前にターミナルで確かめてください。
  - ターミナルで変えた権限モード（Shift+Tab）やモデル（`/model`）は、起動時の値（作成時に指定した値）に戻ります。
- プロセスが終了しているときは、保存値だけを変更し、次の「再起動」で使います。
- ターミナルで直接 `/effort` を実行して変えた場合も、transcript に残る実行結果から読み取り、表示と保存値を合わせます。不正な値などで変更に失敗した場合は変えません。`/effort auto` は「ユーザー設定に従う」として扱います（`/effort auto` は利用者の設定にあるそのモデルの既定も消すため、次の起動はモデルの既定のエフォートになります）。ターミナルでの `/effort` が利用者の設定に保存されるのは Claude Code 本来の動きで、ハブは関与しません。

## 画面の見方と操作

- 左の一覧でエージェントを選択します。状態が「要対応」のエージェントは点滅表示され、未確認の更新があるエージェントには印が付きます。キューに項目がある場合は件数も表示します。
- 「会話」タブは transcript から整形した会話（最新の 300 項目まで。サブエージェント内のやり取りは除く）を、「ターミナル」タブは tmux 画面のスナップショットを表示します。サブエージェントの会話は、一覧のサブエージェントを選ぶと表示できます（[サブエージェントの表示](#サブエージェントの表示)）。
- 入力欄は Enter で送信、Ctrl+Enter（macOS では Cmd+Enter も可）でキューに追加、Shift+Enter で改行します。送り方の違いは[タスクキューと送信](#タスクキューと送信)を参照してください。
- キー送信ボタン（Enter / Esc / 1〜3 / ↑↓ / Shift+Tab / Ctrl+C）で、許可ダイアログや信頼確認に応答できます。
- ショートカット: `Alt+↑↓` 切替、`Alt+1〜9` 選択、`Alt+W` 次の要対応エージェントへ移動。
- 「デスクトップ通知を有効にする」を押して許可すると、選択していない（または画面が裏にある）エージェントが「要対応」「応答完了」「終了」になったときや、新しい対話要求が届いたときに通知します。通知を押すとそのエージェントを選択します。
- ブラウザのタブのタイトルには、要対応または未確認のエージェントの数を表示します。
- tmux のステータス行でも、ウィンドウ名の後に状態を表示し、要対応を赤、実行中を黄、応答完了を緑で色分けします。

### 会話の表示

- アシスタントの回答は、見出し・リスト・表・引用・コードブロックを含む Markdown として表示します。
- ```` ```mermaid ```` のブロックは図として描画します。mermaid はハブに同梱しており、図を表示するときだけハブのサーバから読み込みます（外部の CDN には接続しないので、オフラインでも表示できます。[仕組み](architecture.md#mermaid-の同梱)）。読み込めない場合や図の記法に誤りがある場合は、コードのまま表示します。
- 回答済みの質問・計画・TODO は、カード形式で表示します。
- 発言・回答・ツールの呼び出し・システムの行には、ブラウザの地域の時刻を小さく表示します（今日の分は `14:32`、別の日は `11/11 14:32`）。時刻にポインタを合わせると、秒までの日時を表示します。
- 1 往復（ターン）ごとに、最後の応答の下に所要時間（例: `応答 3分12秒`）を表示します。発言（スキルなどのスラッシュコマンドと、ターンの後に届いた完了通知を含む）から、そのターンの最後の応答までの時間で、質問への回答を待った時間も含みます。ターンの終わりは Claude Code が記録するターンの終了から判断し、記録がなければ次の発言の手前までとします。中断したターンは `中断まで 1分5秒` のように表示します。作業中の最後のターン（経過時間はステータス行に出ます）、表示範囲（最新の 300 項目）の先頭で始まりが欠けているターン、サブエージェントからの報告のように会話に表示しない入力で始まったターン、`/clear` のような応答のないコマンドには表示しません。処理中に送った発言はターンの区切りにしません。
- エージェントが `Read` ツールなどで読んだ画像は、そのツール呼び出しのすぐ下に、利用者がメッセージに貼り付けた画像はそのメッセージの中に、サムネイルで表示します。サムネイルを押すと原寸で表示し（画面より大きい画像はスクロールします）、「新しいタブで開く」で別のタブにも表示できます。
  - 画像は会話とは別に、表示するときにハブのサーバ（`GET /api/agents/<エージェント ID>/images/<参照>`）から読み込みます。会話の読み込みに画像のデータは含めないため、画像を多く読んだセッションでも会話の表示は重くなりません。
  - 表示するのは、そのエージェントの transcript に記録された PNG・JPEG・GIF・WebP の画像だけです。SVG などほかの形式や、サブエージェント内で読んだ画像は表示しません。ハブの画面以外のサイトのページからは読み込めません。

## ブラウザからの回答

Claude Code の対話ダイアログには、画面の「回答待ちパネル」からも回答できます。

| 種類 | 元のツール / イベント | ブラウザでできること |
|---|---|---|
| 質問 | AskUserQuestion | 単一選択・複数選択・その他（自由記述）、選択肢の説明とプレビューの表示、メモの添付、選択せずに返信、回答しない |
| 計画の承認 | ExitPlanMode | Markdown（表・mermaid 図を含む）で計画を表示、承認時のモード選択（auto / 編集を自動承認 / 都度確認）、修正依頼 |
| 権限の確認 | 通常のツール | コマンド・差分・書き込み内容の表示、許可、許可して記憶（提案されたルールの選択）、理由付きの拒否（作業の中断も指定可） |
| 入力要求 | MCP Elicitation | スキーマからフォームを生成（文字列・数値・真偽値・選択肢・複数選択）、送信・辞退・キャンセル、URL モード |

- 「許可して記憶」で適用されるルールと保存先（このセッション / ローカル設定 / プロジェクト設定 / ユーザー設定）はカードに表示され、チェックで選べます。候補は最初からすべて選ばれています。保存先が「このセッション」以外のルールは、Claude Code が設定ファイル（ローカル設定は作業ディレクトリの `.claude/settings.local.json`、プロジェクト設定は `.claude/settings.json`、ユーザー設定は `~/.claude/settings.json`）に書き込むため、ハブの外のセッションにも適用されます。ハブのセッションだけに効かせたい場合は、「このセッション」のルールだけを選んでください。
- 計画を「承認（auto モードで実行）」で承認すると、そのセッションは以降、確認なしでツールを実行します。
- 質問の「回答しない」は、回答を辞退した旨を拒否メッセージで Claude に伝えます（「選択せずに返信」の方式は[既知の制約](#既知の制約)を参照）。
- どのカードにも「ターミナルで回答」があり、押すとブラウザでは回答せず、tmux 上のダイアログに任せます。

### ターミナルとの関係

- 質問・計画の承認・権限の確認（`PermissionRequest` hook）は、TUI のダイアログと**並行して**動作します。ブラウザとターミナルのどちらで回答しても、先に回答した方が採用されます。ターミナル側で先に回答された場合は、後続のイベントから解決済みと判断してパネルから消します。
- 入力要求（`Elicitation` hook）は TUI のダイアログより前に実行されるため、ブラウザで回答を待っている間はターミナル側にダイアログが表示されません。ターミナルで回答する場合は、ブラウザで「ターミナルで回答」を押してください。
- ハブのサーバが停止している場合、hook は待機せずにすぐ TUI に処理を任せます。サーバを停止したときに回答待ちだった要求も、TUI に戻されます。
- ブラウザで約 1 時間回答しなかった要求も、TUI に戻されます。

要求と回答の受け渡しの詳細は、開発ガイド（[CLAUDE.md](../CLAUDE.md#対話要求の受け渡し)）を参照してください。

## タスクキューと送信

入力欄には 2 つの送り方があります。

| 操作 | 動作 |
|---|---|
| 送信（Enter） | 今すぐ送信します。作業中に送った場合は、作業の切れ目で取り込まれます（軌道修正や補足に使います）。取り込まれた発言は、会話タブに「処理中に送信」の目印付きで、送った時点の位置に表示されます |
| キューへ（Ctrl+Enter） | キューの末尾に追加し、現在の作業が終わってから送信します（次の独立したタスクに使います） |

- キューは、エージェントが「応答完了」または「待機中」で、回答待ちのダイアログがないときに、先頭から 1 件ずつ自動で送信されます。キューは 1 エージェントあたり 50 件までで、ハブを再起動しても残ります。
- 入力欄の「/clear」にチェックを入れてキューに追加した項目と、キューのパネルで「/clear」を有効にした項目は、送信前に `/clear` で会話をリセットします（「送信」で今すぐ送る場合は使われません）。本文は、hook のイベントのセッション ID が新しいものに変わる（新しいセッションが始まる）のを待ってから送ります。6 秒ほど待っても変わらない場合は、`/clear` が効いていない会話に本文を送らないよう、項目をキューの先頭に残したまま一時停止し、理由を表示します。ターミナルタブで状態を確かめてから「再開」（または「先頭を今すぐ送信」）を押すと、同じ項目を `/clear` の送信からやり直します（先の `/clear` が遅れて効いていても、もう一度リセットされるのは空の会話です）。`/clear` せずに送る場合は、項目の「/clear」のチェックを外してから再開してください。
- `/` で始まる項目（スラッシュコマンド）は、送った後の様子から扱いを決めます。スキルやカスタムコマンドのようにプロンプトとして展開されるものは、通常の項目と同じく応答が終わるまで「実行中」になります。`/context` のように Claude Code の中だけで処理されるローカルコマンドは hook のイベントを出さないため、会話の記録にコマンドの出力が書かれた時点で「待機中」に戻し、次の項目へ進みます。`/cost` のようにダイアログを開くコマンドは、開いたことも閉じたことも記録に残らずハブから確かめられないため、15 秒ほど待ってもどちらにもならなければ「待機中」に戻してキューを一時停止します（キューが空でも一時停止し、後から追加した項目がダイアログに入力されないようにします）。ターミナルタブでダイアログを閉じてから「再開」してください。
- キューのパネルでは、ドラッグ＆ドロップまたは ↑↓ ボタンでの並べ替え、ダブルクリック（または ✎）での編集、削除、一時停止・再開、「先頭を今すぐ送信」ができます。「先頭を今すぐ送信」は、一時停止中でも先頭の 1 件だけを送ります（エージェントが作業中の場合は送れません）。先頭が古い判断の場合も、提案と照合せずにそのまま送ります。
- 次の場合はキューを自動で一時停止します。
  - エラーで停止した（StopFailure）
  - 実行中にハブのキー送信ボタンから Esc / Ctrl+C で中断した
  - 「/clear」を有効にした項目で、`/clear` の後に新しいセッションを確認できなかった
  - キューから送ったスラッシュコマンドが、プロンプトとして始まらず、出力も記録されないまま 15 秒ほど経った（ダイアログが開いている可能性があります）
  - 最後の利用者の発言より後の応答に、まだ返答していない提案（```` ```proposals ```` ブロック）がある（判定は[提案の仕分け](#提案の仕分け)のボードの自動表示と同じです）
  - キューの先頭にある提案への判断が古くなった（判断をキューに入れた後、送る前に新しい提案が出た、または対象の提案にターミナルや入力欄から先に返答した）
  - 「引き継いでリセット」を実行している（終わると元の状態に戻ります。[コンテキスト量と引き継いでリセット](#コンテキスト量と引き継いでリセット)）
- 提案があるために一時停止した場合は、「再開」を押しても、提案に返答するまで再び一時停止します。仕分けボードの「判断を送信」または「キューに追加」で返答するか、入力欄から送信してください。仕分けボードの「キューに追加」を使うと、判断はキューの先頭に入り、提案による一時停止を解除して、ほかの項目より先に自動で送信します。判断を送ると提案に返答したことになるため、続く項目も順に送信します（新しい提案が出た場合は再び一時停止します）。手動や中断、`/clear` の未完了、スラッシュコマンドの終了を確認できなかったことによる一時停止中に判断を追加した場合は、一時停止したまま先頭に入り、「再開」すると判断から送信します。
- キューに入れた判断は、どの提案への判断かを記録しており、送る前に対象の提案がまだ判断待ちかを確かめます。判断待ちのままならそのまま送信し、古くなっていれば別の提案への返答として送られないよう、送らずに一時停止して理由を表示します。このとき（手動などほかの理由で一時停止している間も、先頭が古い判断であれば）、キューのパネルには「再開」の代わりに「古い判断を削除して再開」と「古い判断を送って再開」が表示されます。内容を確かめ、今の会話にそのまま送る場合は「古い判断を送って再開」を、送らない場合は「古い判断を削除して再開」を押してください。書き直してから送る場合は、編集してから「古い判断を送って再開」を押します。会話を読み込めないなどで画面が古いかどうかを確かめられない間も、古い判断を理由に一時停止していれば、この 2 つのボタンを表示します。画面で古いかどうかをまだ確かめられていないときなど、通常の「再開」を押した場合は、古い判断をそのまま送らず、送る前にその時点の会話で照合し直します。まだ古ければその時点の理由で再び一時停止し、対象の提案が判断待ちであれば通常どおり送信します。新しい提案への判断を仕分けボードの「キューに追加」で入れた場合は、一時停止を解除して新しい判断から送信します（古い判断は後ろに残り、順番が来たときに改めて一時停止します）。
- キューのパネルでは、提案への判断の項目に「提案への判断」の目印と左端の線を付けて、通常の項目と見分けられるようにしています。判断は先頭にある間は提案による一時停止をせずに送信されますが、ほかの項目を判断より前に移すと一時停止することがあります。対象の提案がもう判断待ちでない（新しい提案が出た、または返答済みの）判断には「古い判断」の目印を付けます。順番が来ると送らずに一時停止するので、不要であれば削除してください。目印にポインタを合わせると説明を表示します。
- **送信ガード**: 回答待ちのダイアログがある間、ターミナルでダイアログが表示されている（状態が「要対応」の）間、起動中、プロセスの停止中は、tmux への送信を拒否します（ダイアログへの誤入力を防ぐため）。その場合はダイアログに回答するか、キューに追加してください。

## 提案の仕分け

ハブから起動したエージェントには、追加のシステムプロンプト（`--append-system-prompt`）で「個別に判断してほしい提案は ```` ```proposals ```` ブロック（JSON）で示す」よう指示しています。この指示は、新規作成時と再起動時（`--resume` で再開する場合を含む）に毎回渡します。

- 仕分けの対象は ```` ```proposals ```` ブロックのある応答だけです。ブロックのない通常の箇条書きは対象になりません。ブロックの中身が JSON として読めない場合は、ブロック内の箇条書きを項目として読み取ります。
- 最後の利用者の発言より後の応答に、まだ返答していない提案ブロックがあると、仕分けボードが自動で開きます。
- 各提案カードを「採用 / 却下 / 修正して実施 / 未判断」の列へドラッグ＆ドロップするか、カードのボタンやキー（A 採用 / X 却下 / E 修正 / U 戻す）で仕分けます。「修正して実施」では修正内容を入力します（未入力のままでは送信できません）。「残りをすべて採用」で、未判断の項目をまとめて採用にできます。
- カードをクリックするか、カードにフォーカスして Enter を押すと、その提案を拡大表示します。見出しと補足を大きな文字で表示し、補足は Markdown（箇条書き・強調・コードなど）として描画します。拡大表示の中でも、ボタンやキー（A / X / E / U）で判断し、「修正して実施」の修正内容を入力できます。「前へ」「次へ」または ← → キーで、提案に書かれた順に前後の提案へ移動します。Esc・「閉じる」・背景のクリックで閉じると、判断と修正内容がボードに反映された状態に戻ります。
- 「判断を送信」で、仕分け結果と全体へのコメントを整形した文章として Claude に送ります。未判断の項目は「保留」として伝えます。「キューに追加」を選ぶと、提案への返答としてキューの先頭に追加し、ほかの項目より先に送信します（提案によるキューの一時停止もこのとき解除します。送る前に新しい提案が出た場合は、判断を送らずに一時停止します。[タスクキューと送信](#タスクキューと送信)）。
- 閉じたボードは、提案ブロックのある応答の右下にある「仕分ける」から開き直せます。ボードを閉じても提案に返答したことにはならないため、キューは一時停止したままです。
- 仕分けの途中経過はブラウザ（localStorage）に保存されるため、画面を閉じても続きから再開できます。保存するのは新しいものから 100 件までです。

## サブエージェントの表示

エージェントが Agent ツールで起動したサブエージェントは、左の一覧で親エージェントの下にツリー状に表示します。サブエージェントがさらに起動したサブエージェントは、その下に字下げして表示します。

- 各行には、親エージェントの半分の大きさの猫（毛色は親と同じ）、Agent ツールに渡した説明（`description`）、経過時間を表示します。行にマウスを重ねると、状態と作業内容を表示します。
- 状態は次のとおりです。猫の様子は[猫のステータス表示](#猫のステータス表示)と同じ対応です。

  | 状態 | 判定 |
  |---|---|
  | 実行中 | 終了の記録がなく、今の親エージェントのプロセスで記録が更新されている（作業内容は最後のツール呼び出し。ツールを使っていなければ「思考中」）。完了の後に再開されて記録が続いているものも含みます |
  | 要対応 | そのサブエージェントのツール呼び出しで、権限の確認などの回答を待っている（回答は親エージェントの回答待ちパネルから行います） |
  | 完了 | 終了の記録がある |
  | 失敗 | 親エージェントへの完了通知で失敗と報告された |
  | 中断 | 終了の記録がないまま親エージェントのプロセスが終了した（親を再起動した後も、前のプロセスで止まったものは中断のままです）、停止された、またはフォアグラウンドのサブエージェントで親の応答が終わった |

- 経過時間は、実行中・要対応のものは開始からの時間、それ以外は終わってからの時間です。
- 一覧が長くなりすぎないよう、終わったサブエージェントは親ごとに新しいものから 3 件だけを表示し、それより古いものは「完了した N 件を表示」にまとめます（押すとすべて表示し、「古い完了分を隠す」で戻します）。作業中のものは常に表示します。
- 親エージェントの行の「▾ サブ 作業中の数/全体の数」を押すと、そのエージェントのツリーを折りたたみます（設定はブラウザに保存されます）。
- サブエージェントを選ぶと、その会話を読み取り専用で表示します。指示の送信、キー送信、キュー、回答待ちパネル、提案の仕分けは表示せず、「親エージェントを表示」で親エージェントの表示に戻ります。会話の中の画像は表示しません。
- 表示するのは、親エージェントの現在のセッションのサブエージェントだけです。`/clear` などで新しいセッションになると、それまでのサブエージェントは一覧から消えます。
- サブエージェントの情報は、Claude Code が親のセッションの記録と同じ場所（`~/.claude/projects/<作業ディレクトリ>/<セッション ID>/subagents/`）に保存する記録から読み取ります（[仕組み](architecture.md#サブエージェントの状態)）。

## コンテキスト量と引き継いでリセット

長いセッションは応答のたびにそれまでの会話をすべて読み直すため、トークンの消費が増え、古い話に引きずられやすくなります。区切りのよいところで新しいセッションに切り替えられるよう、会話の大きさを表示し、引き継ぎを自動で行う操作を用意しています。

### コンテキスト量の表示

- 一覧のカードと詳細のステータス行に、現在のコンテキスト量を `ctx 12.3万` のように表示します（1 万未満は `ctx 8,500` のように表示します）。ポインタを合わせると正確なトークン数を表示します。
- 量は、transcript の最新の応答（サブエージェント内のやり取りを除く）の入力の量（`input_tokens`・`cache_creation_input_tokens`・`cache_read_input_tokens` の合計）です。応答が届いた後に更新されるので、表示は直前の応答の時点の量です。会話がまだない場合や `/clear` の直後は表示しません。
- 目安（既定 150,000 トークン。[設定](configuration.md)の `HUB_CONTEXT_WARN_TOKENS`）を超えると、表示を警告の色にして「⚠」を付け、詳細のステータス行には「切り替え推奨」を添えます。

### 引き継いでリセット

詳細画面の「引き継いでリセット」を押し、確認ダイアログで OK すると、ハブが次の 3 段階を自動で進めます。進行中は、ステータス行の下に段階（1/3・2/3）を表示します。

1. 引き継ぎメモ（進行中の作業・決定事項・未解決の点・次にやること・関係するファイルや Issue など）を、応答として ```` ```handoff ```` ブロックに書くよう指示します。
2. 応答が終わったら、transcript からメモを取り出して保存し、`/clear` を送ります。ブロックがない応答の場合は、指示より後の応答の本文をすべてメモにします。
3. 新しいセッションが始まったら、最初の指示として「前のセッションからの引き継ぎです。次の引き継ぎメモを読んで、続きから作業を再開してください」という文にメモを付けて送ります。

- ボタンは、状態が「応答完了」または「待機中」で、回答待ちの要求がなく、会話があるときだけ押せます。押せないときは、ボタンにポインタを合わせると理由を表示します。
- 実行中は、入力欄からの送信（送信ガード）とキューの自動送信を止めます。キューへの項目の追加・編集・並べ替え・削除はできますが、一時停止・再開・「先頭を今すぐ送信」はできません。終わったら、キューの一時停止の状態を実行前に戻します（実行中にハブのキー送信ボタンで中断したなど、別の理由で一時停止し直した場合はその一時停止を残します）。
- 次の場合は `/clear` を送らずに中止し、理由を表示します: メモの応答が空だった、作成中に確認や質問の回答待ちになった、中断された、エージェントやセッションが終了した、ターミナルでセッションが切り替えられた、15 分以内に応答が終わらなかった。
- `/clear` の後に新しいセッションを 60 秒以内に確認できなかった場合なども中止し、保存したメモの場所を表示します。メモを読み返して、手動で指示を送ってください。
- 実行中にエージェントが終了した場合や、エージェントが再起動された・ターミナルの `/resume` などで別の会話が再開された場合も中止し、`/clear` を送った後であれば保存したメモの場所を表示します。再起動後のセッションには、セッション ID が変わっていても再開の指示を送りません（送った `/clear` による新しいセッションではないため）。
- 結果（完了・中止とその理由、メモの保存先）は、「閉じる」を押すまで表示します。
- メモは作業ディレクトリには書かず、ハブのデータ置き場の `handoffs/<エージェント ID>-<作成時刻（UTC）>.md` に保存します（[データの保存先](architecture.md#データの保存先)）。エージェントを削除しても残ります。
- ハブのサーバが途中で再起動しても、保存した段階から続きを進めます。`/clear` を送るのはメモを保存した後だけなので、メモのないまま `/clear` だけが送られることはありません（[仕組み](architecture.md#引き継いでリセットの進め方)）。

## 利用上限の表示

サイドバーのエージェント一覧の上に、Claude の利用上限（claude.ai のプラン）の使用率を、5 時間の枠と週の枠の 2 本のバーで表示します。

- 利用上限はアカウント単位なので、エージェントごとではなく 1 か所に表示します。どのエージェントから受け取った値も同じ上限を指し、ハブは最後に受け取った値を表示します。
- 各バーの下にリセットの時刻と残り時間を、一番下に値を受け取ってからの経過時間を表示します。バーにポインタを合わせると、受け取った時刻を含む詳細を表示します。
- 使用率が 70% 以上で黄、90% 以上で赤にします。
- 値は、ハブのエージェントが応答したときに Claude Code から届きます。ハブの外（claude.ai や別の端末の Claude Code）での利用分は、次にハブのエージェントが応答するまで反映されません。受け取ってから 15 分を過ぎた値は、古い値として薄く表示します。
- リセットの時刻を過ぎた枠は、バーを出さずに「リセット済み」と表示します。新しい使用率は、次にエージェントが応答したときに届きます。
- 値をまだ受け取っていない場合（ハブを起動してからエージェントが一度も応答していない、API キーや Bedrock・Vertex などで利用しているなど）は「不明」と表示します。値は `AGENT_HUB_HOME` の `usage.json` に保存するので、ハブを再起動しても前回の値を表示します。

### ステータスラインとの関係

使用率は、Claude Code がステータスラインのコマンドに渡す情報から受け取ります。そのため、ハブが起動するエージェントには、ハブのステータスラインのコマンドを設定します（[仕組み](architecture.md#利用上限の受け取り)）。

- 利用者の設定（`~/.claude/settings.json`。`CLAUDE_CONFIG_DIR` を指定している場合はその下）や、作業ディレクトリの `.claude/settings.local.json`・`.claude/settings.json` にステータスラインがある場合は、ハブのコマンドがそのコマンドを同じ入力で実行し、出力をそのまま表示します。複数ある場合は Claude Code と同じく、作業ディレクトリのローカル設定、作業ディレクトリの設定、利用者の設定の順に最初に見つかったものを使います。
- ステータスラインの設定がない場合は、ステータスラインには何も表示しません。
- 管理者の設定（managed settings）にステータスラインがある場合は、そちらが優先されるため、使用率を受け取れません（「不明」のままになります）。

## 猫のステータス表示

各エージェントの状態を、ドット絵の猫のアニメーションで表示します（サイドバーのカードと、詳細画面上部のステータス行の帯）。サブエージェントは、一覧のツリーに小さい猫で表示します。

| 状態 | 猫の様子 |
|---|---|
| 実行中（ツール使用中） | 歩く（ステータス行の帯では左右に往復） |
| 実行中（思考中） | お座りして「…」 |
| 要対応 | 前足を振って「！」 |
| 応答完了（1 分以内） | 目を細めてしっぽを振り「♪」 |
| 待機中・応答完了 | お座り（ときどきまばたき） |
| 待機中・応答完了が 5 分以上続く | 丸まって昼寝（Zzz） |
| 起動中 | あくび |
| 圧縮中 | 毛づくろい |
| 終了（サブエージェントの失敗・中断を含む） | 灰色で眠る |

- 毛色は作成時に選択できます（茶トラ / サバトラ / クリーム / シャム / 黒猫 / 三毛）。「おまかせ」の場合はエージェント ID から決まります。
- サイドバー下部の「猫のアニメーション: オン / オフ」で、アニメーションを止めて静止画にできます。設定はブラウザに保存されます。OS の「動きを減らす」設定には連動せず、既定ではアニメーションします。
- スプライトは `public/cats.js` に文字列で定義しています。

## 既知の制約

- Esc / Ctrl+C による中断では Stop hook が発火しないため、ハブのキー送信ボタンから送った場合のみ「待機中」に戻します。tmux 側で直接中断した場合は、次のイベントが届くまで状態が「実行中」のまま残り、その間はキューも送信されません。
- 信頼確認ダイアログはセッション開始前に表示されるため、hook では検知できません（状態は「起動中」のままになり、送信ガードにより入力欄からは送信できません）。キー送信ボタンで応答してください。
- 質問の「選択せずに返信」は、拒否メッセージとして Claude に返信内容を伝える方式です。
- ターミナルタブは色なしのスナップショット表示です。
- 利用者のステータスラインのコマンドは、ハブのコマンドを経由して実行するため、5 秒で打ち切ります。また、`padding` などコマンド以外の項目は Claude Code が設定をまとめた結果に従います。
